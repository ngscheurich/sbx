# ADR-0007: Style output with Charm's v2 stack

sbx styles its own user-facing output — the plan and status reports, help, and the `sbx: …` error lines — with Lip Gloss **v2** (`github.com/charmbracelet/lipgloss/v2`) rather than stable v1. v2's `colorprofile` binds the color profile to the writer rather than the process: `ui.Writers` wraps the `stdout`/`stderr` writers `cli.Run` receives, and an `Ascii`-profile writer strips every escape before output. Degrade-by-destination is therefore structural — a pipe or `NO_COLOR` cannot receive ANSI no matter what a renderer emits — which keeps plain output byte-identical to pre-styling output as a golden-tested invariant, and lets every renderer be a single code path parameterized by styles with no plain variant. v1 would have met the functional need, but its process-global termenv detection would have made the pipe-safety property a testing obligation instead of a structural one; the accessibility guide's earlier termenv assumption is updated with this ADR. Decoration is limited to color and bold from the named 16-color ANSI palette, with color never carrying meaning without its word, per `docs/style/accessibility.md`.

The explicit `--plain` flag that guide calls the accessibility lever is deferred: under writer-bound profiles it strips nothing today. It ships with the first non-color decoration (border, glyph, or in-place redraw), tracked as `.tracker/output-styling/issues/03-plain-lever.md`.

Update: the trigger arrived as predicted. The drift report's bordered table became sbx's shared table style (`ui.Table`), drawn by `sbx list` as well, and `--plain` (alias `--no-color`) shipped in the same change: it forces the fully-stripping writer profile and drops table borders, so a reader who asks for no decoration gets none at a terminal either.

Revisit if a non-color decoration lands before `--plain` does, or if Lip Gloss v2's profile detection proves unable to honor an environment the guide requires.
